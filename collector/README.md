# אוסף נתוני השימוש — הקמה חד-פעמית

עד שההקמה הזאת מתבצעת, **הכלי לא אוסף כלום**. `usage.js` מגיע עם `ENDPOINT` ריק,
ובמצב הזה הוא לא שולח בקשה אחת ולא מציג שום הודעה למשתמשים.

## מה בונים כאן

| רכיב | תפקיד |
|------|-------|
| `worker.js` | Cloudflare Worker. מקבל אירועים אנונימיים, ומחזיר סיכומים למי שמחזיק את הטוקן |
| `schema.sql` | טבלאות D1. שורה לכל אירוע — אין בהן עמודה שיכולה להחזיק טקסט שמישהו הקליד |
| `selftest.mjs` | מריץ את ה-Worker האמיתי מול SQLite אמיתי. מוכיח את ה-SQL לפני פריסה |

**למה Worker ולא שירות אנליטיקה חינמי:** בדקתי — ב-GoatCounter וב-Umami ה-API
לקריאת הנתונים הוא חלק מהמסלול בתשלום. בלי API אין דשבורד מקומי, רק הדשבורד שלהם
באתר שלהם. מעבר לכך, המדדים שביקשת (כמה לוחות נוצרו, כמה זמן לוקח מהתחלה ועד סוף,
אילו יישובים נוספו בחיפוש) הם צבירות ייעודיות שכלי אנליטיקה כללי לא יודע לחשב.

**עלות:** אפס. המסלול החינמי של Cloudflare Workers הוא 100,000 בקשות ליום,
ושל D1 — 100,000 כתיבות ליום ו-5GB. לוח אחד שנוצר הוא כ-10 שורות.

## הקמה

### 1. חשבון Cloudflare
היכנסו ל-<https://dash.cloudflare.com/sign-up> ופתחו חשבון חינמי.
**את זה צריך לעשות בעצמך** — אני לא פותח חשבונות.

### 2. wrangler
```
npm install -g wrangler
wrangler login
```

### 3. מסד הנתונים
```
cd collector
wrangler d1 create zmanei-nezach-usage
```
העתיקו את `database_id` שהפקודה מדפיסה אל `wrangler.toml`, במקום `PASTE_DATABASE_ID_HERE`.

```
wrangler d1 execute zmanei-nezach-usage --remote --file=schema.sql
```

### 4. טוקן הגישה לדשבורד
ייצרו מחרוזת אקראית ארוכה (למשל `openssl rand -base64 32`), ואז:

```
wrangler secret put ADMIN_TOKEN
```

**שמרו את אותה מחרוזת ב-Bitwarden Secrets Manager** — הדשבורד המקומי מושך אותה
משם בזמן ריצה. אל תכתבו אותה בשום קובץ בפרויקט.

### 5. פריסה
```
wrangler deploy
```
הפקודה מדפיסה כתובת בסגנון `https://zmanei-nezach-usage.<שם>.workers.dev`.

### 6. הפעלת האיסוף באתר
פתחו את `usage.js` בשורש הפרויקט ושימו את הכתובת:

```js
ENDPOINT: 'https://zmanei-nezach-usage.<שם>.workers.dev',
```

**ברגע שהשדה הזה מתמלא, מופיעה מאליה הודעת גילוי למשתמשים** בעמוד הכניסה — היא
מרונדרת מאותו דגל שמפעיל את השליחה, כדי שאי אפשר יהיה להפעיל איסוף בלי לספר עליו.

הוסיפו את כתובת האתר ל-`ALLOWED_ORIGINS` שבראש `worker.js` אם היא שונה, ופרסו שוב.

### 7. הדשבורד
```
cd dashboard
copy settings.local.cmd.example settings.local.cmd
```
מלאו שם את `ZN_COLLECTOR` ואת `ZN_TOKEN_SECRET_ID` (מזהה הסוד ב-Bitwarden).
הקובץ הזה לא נכנס ל-git.

מכאן — קיצור הדרך **"זמני נצח - שימוש הציבור"** שעל שולחן העבודה מושך את הנתונים
ופותח את הדשבורד.

## בדיקה לפני פריסה

```
node collector/selftest.mjs
```

מריץ את ה-Worker האמיתי מול SQLite בזיכרון ובודק, בין השאר, ששם פרטי שנשלח
בזדון לא נשמר, שעיצוב שאינו אחד מהעשרה נדחה, ושהממוצע של זמן היצירה מתעלם
מלוחות שנוצרו מהגדרות קיימות.

## מה לא נאסף, לעולם

שם הנפטר/ת, שורת התאריך, משפט שנכתב אישית, התמונה, ושם יישוב שהמשתמש הקליד או
ערך. יישוב שנוסף בחיפוש מדווח לפי **השם שבמאגר שלנו** הקרוב ביותר לקואורדינטות
שלו, ולכן המחרוזת שיוצאת מהמכשיר היא תמיד שלנו ולא של המשתמש.

הסיבה איננה טכנית. עמוד הכניסה מבטיח למשפחות, במילים האלה:

> "הכול נשמר במכשיר שלכם בלבד — אין כאן חשבון משתמש ואף אחד אחר לא רואה את מה שהזנתם."

## כיבוי

מחקו את הכתובת מ-`ENDPOINT` ב-`usage.js`. זה מספיק: השליחה, ההודעה למשתמשים
והכול — הכול תלוי בשדה האחד הזה. למחיקה מלאה, מחקו את `usage.js` ואת שורת
ה-`<script>` שלו; שש הקריאות ב-`app.js` עטופות ב-`if (window.ZN_TRACK)` ולכן
לא ישברו.
